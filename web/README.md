# Сайт «Толмача»

Next.js, App Router. Работает поверх того же ядра, что и консоль: ядро лежит
в `../src`, собирается в `../dist` командой `npm run build:core` и исполняется
только на сервере — ни разбор HTML, ни клиент Anthropic в браузер не попадают.

## Запуск

```
npm run сайт          # из корня репозитория: собирает ядро и поднимает сайт
```

Репозиторий устроен рабочими пространствами: один `npm install` в корне ставит
и консоль, и сайт.

### Если не поднялось на телефоне

Next по умолчанию собирает Turbopack — это родной бинарник, собранный под
glibc или musl. В Termux libc третья, bionic, и такой бинарник может не
загрузиться вовсе. Тогда:

```
npm run сайт-запасной
```

Это тот же сайт на старом сборщике, который умеет откатываться на
WASM-версию компилятора: медленнее, но не зависит от родных бинарников.
Проверить это на Android у меня возможности не было — если и запасной путь
не пойдёт, сайт нужно поднимать на компьютере или на сервере, а телефон
оставить тем, чем он и является: читалкой.

Ключ берётся из `ANTHROPIC_API_KEY` — того же `.env` в корне, что и у консоли.
Без ключа сайт поднимется и будет листаться, но на попытке перевести честно
скажет, что переводить нечем.

## Развернуть на Vercel

Собирать умеет он сам из GitHub — ставить ничего не нужно, хватит телефона.

1. `vercel.com` → **Add New… → Project** → выбрать репозиторий `ExtTran`.
2. **Root Directory** → `web`. Остальное Vercel определит сам: корневые
   рабочие пространства он видит и ставит зависимости для всего репозитория.
3. **Environment Variables** → `ANTHROPIC_API_KEY`. Только здесь, никогда
   в репозитории и никогда в переписке.
4. Deploy.

Сборка сама поднимет ядро: `build` в этом пакете — это
`tsc -p ../tsconfig.core.json && next build`. Готового `dist/` в репозитории
нет и быть не должно, он собирается каждый раз заново.

### Три вещи, о которых стоит знать заранее

**Глава переводится дольше, чем живёт обычный запрос.** Замер дал от 58 до
130 секунд. У маршрута выставлено `maxDuration = 300`, но такой потолок
доступен только на Fluid Compute — проверьте, что он включён, иначе длинные
главы будут обрываться на середине.

**Ссылка публичная, а ключ ваш.** Входа и квоты ещё нет: любой, кто узнает
адрес, сможет переводить главы за ваш счёт — по 2.87 ₽ за штуку. Пока нет
учётных записей, закройте развёрнутый сайт паролем: Settings → Deployment
Protection. Это одна настройка, и она стоит между вашей картой и интернетом.

**Правила писал не юрист.** В `docs/rights-policy.md` это сказано прямо, и там
же лежат вопросы к юристу. Публично доступный сайт, который переводит чужие
книги, — это уже запуск, а не черновик.

## Что уже есть

| Путь | Что это |
| --- | --- |
| `/` | Главная: поле для ссылки и выбор регистра. Форма обычная, методом GET — работает и без скриптов |
| `/read` | Ридер: перевод приходит потоком и показывается по абзацу |
| `/rules` | Правила: что мы делаем с чужим текстом |
| `/api/translate` | Перевод построчным JSON — по кадру на строку |

## Почему перевод идёт потоком

Глава переводится от минуты до двух. Ждать столько перед пустым экраном никто
не станет, поэтому ответ отдаётся кадрами: сначала заголовок и длина, потом
текст по мере готовности, в конце — сколько это стоило.

## Чего ещё нет

**Глоссария.** Он собирается по книге и должен лежать в хранилище, которого
пока нет, — поэтому сайт переводит без него, то есть ровно настолько же
машинно, как все остальные. Это главное, что предстоит исправить: без
глоссария продукт не отличается от бесплатного переводчика.

Дальше: каталог, кабинет с квотой, вход и оплата, хранение переводов.

## Про проверку ссылки

`lib/source.ts` пропускает только http(s) и только наружу: в консоли
`loadChapter` принимает и путь к файлу, но на сервере это означало бы, что
любой посетитель может попросить прочитать файл с нашего диска. Проверка идёт
по имени хоста и не ловит подмену DNS между проверкой и запросом — настоящая
защита от хождения внутрь сети делается на уровне сети, и её ещё нет.
